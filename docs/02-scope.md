# Project scope

This case study delivers architecture documentation and an
implementation plan for an enterprise Azure Landing Zone.

The planned foundation supports five application teams across
development, test, and production environments. The employee
portal is the pilot application.

## In scope

1. **Requirements:** Document business and technical requirements
   and define acceptance criteria.

2. **Target architecture:** Create diagrams and explain how Azure,
   the pilot application, and the existing data centre interact.

3. **Security and governance:** Define access controls, security
   checks, monitoring, and cost ownership.

4. **Migration planning:** Plan the employee portal migration,
   including dependencies, testing, and rollback procedures.

5. **Operations and handover:** Define support responsibilities,
   operational documentation, and handover acceptance criteria.

6. **Effort and risks:** Provide an initial effort estimate and
   document assumptions, dependencies, and risks.

## Out of scope

- Detailed migration planning for every enterprise application.
  The employee portal is the initial pilot.
- Replacement or migration of the existing HR system.
  It remains on-premises and must integrate with the portal.
- Development of new portal features or a complete application rewrite.
- Actual production deployment and ongoing managed operations.
  These would require a separate implementation engagement.

## Scope changes

Any proposed scope change must be assessed for its impact on
architecture, effort, cost, and schedule. The project sponsor
decides whether to approve the change.
